# 光何管理系统（gsite）详细设计文档

> 版本：2026.11-jdk25-SNAPSHOT　｜　文档范围：本仓库当前主干（`main`）实际存在的代码
> 说明：本文只描述**代码里真实存在**的模块与实现，已经物理移除的模块（AI、ERP、IoT、商城等）不在范围内。

## 1. 项目概述

### 1.1 定位

一套**单体多模块**的企业级后台快速开发平台：

- 后端：Spring Boot 单体应用，按「框架层（framework）+ 业务模块层（module）+ 启动层（server）」垂直切分；
- 前端：Vue3 + Element Plus 管理后台，菜单与按钮权限由后端动态下发；
- 交付：Windows/Linux 一体机部署包（Nginx + MySQL + Redis + 内置 JRE + 启停脚本），并内置「系统在线更新」能力。

### 1.2 技术选型

| 层次 | 技术 | 说明 |
|---|---|---|
| 语言/运行时 | Java 25 | 根 `pom.xml` 中 `java.version=25` |
| 框架 | Spring Boot 3.5.14 | `spring.boot.version` |
| 构建 | Maven 多模块 + flatten-maven-plugin | 统一版本号 `${revision}` |
| 持久层 | MyBatis-Plus、mybatis-plus-join、dynamic-datasource、Druid | 逻辑删除、字段自动填充、多数据源 |
| 数据库 | MySQL 为主 | `sql/` 另附 dm/kingbase/oracle/postgresql/sqlserver/opengauss/highgo/db2 脚本 |
| 缓存 | Redis + Redisson + Spring Cache | 默认 TTL 1h |
| 消息 | Redis Stream / PubSub（默认），可选 RabbitMQ、Kafka、RocketMQ | 见 `guanghe-spring-boot-starter-mq` |
| 调度 | Quartz（JDBC JobStore） | `qrtz_*` 表 |
| 安全 | Spring Security + 自研 OAuth2 令牌 | Token 存 `system_oauth2_access_token` |
| 接口文档 | springdoc + Knife4j | 按模块 `GroupedOpenApi` 分组 |
| 前端 | Vue3 + TypeScript + Vite + Element Plus + Pinia + UnoCSS + ECharts + form-create | `guanghe-ui/guanghe-ui-admin-vue3` |
| 验证码 | anji-plus captcha（Redis 缓存） | 滑块/点选/文字 |

## 2. 工程结构与模块划分

```
gsite/
├─ guanghe-dependencies/     依赖版本 BOM（统一管理三方版本）
├─ guanghe-framework/        框架层：15 个自动装配 Starter
├─ guanghe-module-system/    系统模块：用户、权限、租户、通知、短信、邮件、OAuth2…
├─ guanghe-module-infra/     基础设施模块：代码生成、文件、配置、任务、日志、系统更新…
├─ guanghe-server/           启动模块：GuangheServerApplication + 配置文件
├─ guanghe-ui/guanghe-ui-admin-vue3/   管理后台前端
├─ sql/                      各数据库建表与初始化数据脚本
├─ script/                   docker / jenkins / shell / idea 辅助脚本
└─ release/gsite-deploy/     一体化部署包（nginx、mysql、redis、jre、启停脚本）
```

依赖方向（单向，禁止反向依赖）：

```
server ──▶ module-* ──▶ framework-* ──▶ common
                     └▶ dependencies(BOM)
```

模块之间**不直接注入对方的 Mapper/Service**，只通过对方暴露的 `api` 包（如 `guanghe...system.api.user.AdminUserApi`）交互，避免模块间强耦合。

## 3. 框架层（guanghe-framework）详细设计

每个 Starter 都是「自动装配 + 可覆盖的扩展点」结构：`config/*AutoConfiguration` 负责装配，`core/*` 放置能力实现，`src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 声明自动装配类。

### 3.1 guanghe-common（公共内核）

| 分类 | 关键类 | 用途 |
|---|---|---|
| 统一响应 | `pojo/CommonResult`、`PageParam`、`PageResult`、`SortablePageParam` | 所有接口统一返回 `{code,data,msg}`；分页参数与结果基类 |
| 错误体系 | `ErrorCode`、`ServiceException`、`ServerException`、`ServiceExceptionUtil`、`GlobalErrorCodeConstants`、`ServiceErrorCodeRange` | 业务异常统一 `code + msg`；错误码 10 位四段制（类型-系统-模块-序号），模块区间在 `ServiceErrorCodeRange` 中登记：infra `[1-001-000-000, 1-002-000-000)`、system `[1-002-000-000, 1-003-000-000)` |
| 跨模块 API | `biz/system/*`、`biz/infra/*` | 只依赖接口和 DTO，不依赖具体模块（`DictDataCommonApi`、`OAuth2TokenCommonApi`、`ApiAccessLogCommonApi` …） |
| 工具 | `util/json`、`util/collection`、`util/date`、`util/object/BeanUtils`、`util/servlet`、`util/spring` | JSON（Long→String、时间戳序列化）、集合、日期、Bean 拷贝、请求上下文 |
| 校验 | `validation/InEnum`、`Mobile`、`Telephone` | 枚举/手机号/固话校验注解 |
| 枚举 | `UserTypeEnum`、`TerminalEnum`、`CommonStatusEnum`、`DateIntervalEnum`、`WebFilterOrderEnum` | 全局枚举与过滤器顺序约定 |

### 3.2 guanghe-spring-boot-starter-web（Web 基础）

| 子能力 | 关键类 | 设计说明 |
|---|---|---|
| 统一前缀 | `web/config/WebProperties` | `/admin-api`（`**.controller.admin.**`）、`/app-api`（`**.controller.app.**`）两套 API 前缀，由 `WebFrameworkUtils` 自动按包路径拼前缀 |
| 全局异常 | `web/core/handler/GlobalExceptionHandler` | 统一处理 `ServiceException`、参数校验、`AccessDeniedException`、兜底 `Exception`，并写 `infra_api_error_log` |
| 请求工具 | `web/core/util/WebFrameworkUtils` | 取登录用户、租户、终端、请求路径等 |
| 访问日志 | `apilog/*`（`@ApiAccessLog`、`ApiAccessLogFilter`、`ApiAccessLogInterceptor`） | 方法级注解 + 过滤器双通道采集，落 `infra_api_access_log` |
| 数据脱敏 | `desensitize/*` | 注解式脱敏：`@MobileDesensitize`、`@IdCardDesensitize`、`@BankCardDesensitize`、`@EmailDesensitize`、`@PasswordDesensitize`、`@ChineseNameDesensitize` 等，JSON 序列化时生效 |
| XSS | `xss/*` | Jsoup 清洗请求体/参数（当前 `guanghe.xss.enable: false`） |
| 报文加密 | `encrypt/*` | `@ApiEncrypt`，AES/RSA（当前 `guanghe.api-encrypt.enable: false`） |
| Jackson | `jackson/*` | Long 序列化为字符串、`LocalDateTime` 用时间戳、BigNumber 精度保护 |
| Swagger | `swagger/*` + `GuangheSwaggerAutoConfiguration.buildGroupedOpenApi("system")` | 每个模块在自己的 `framework/web/config` 里声明分组 |
| 启动横幅 | `banner/*` | 启动时打印项目信息 |

### 3.3 guanghe-spring-boot-starter-mybatis（持久层）

- `BaseDO`：`createTime/updateTime/creator/updater/deleted`，`@TableField(fill=…)` 自动填充，`@TableLogic` 逻辑删除；`clean()` 用于清空审计字段防止前端回填。
- `BaseMapperX<T>`：在 MyBatis-Plus `BaseMapper` 之上提供 `selectPage`、`selectList(field, value)`、`insertBatch`、`selectOne` 等便捷方法，业务 Mapper 一律继承它。
- `LambdaQueryWrapperX` / `QueryWrapperX` / `MPJLambdaWrapperX`：`xxxIfPresent` 系列方法，条件为空自动跳过，避免 Service 里写 `if (StrUtil.isNotBlank(...))`。
- `DefaultDBFieldHandler`：`MetaObjectHandler` 实现，填充审计字段（取 `SecurityFrameworkUtils.getLoginUserId()`）。
- 类型处理器：`LongListTypeHandler`、`StringListTypeHandler`、`IntegerListTypeHandler`、`LongSetTypeHandler`、`EncryptTypeHandler`（字段级 AES 加密，密钥 `mybatis-plus.encryptor.password`）。
- `GuangheDataSourceAutoConfiguration`：关闭 Druid 自动配置，改用 `dynamic-datasource`（`master` / `slave`，从库 `lazy: true`）；`DruidAdRemoveFilter` 去广告。
- `IdTypeEnvironmentPostProcessor`：按数据库类型自动决定主键策略（MySQL 自增 / Oracle 等 `INPUT` + `@KeySequence`）。
- `translate/*`：Easy-Trans 数据翻译（`easy-trans.is-enable-global: false`，默认关闭全局翻译，按需使用 `@Trans`）。

### 3.4 guanghe-spring-boot-starter-redis

- `GuangheRedisAutoConfiguration`：Redisson 客户端 + `RedisTemplate` 序列化配置。
- `GuangheCacheAutoConfiguration` / `TimeoutRedisCacheManager`：Spring Cache 基于 Redis，支持 `@Cacheable(cacheNames, key, timeUnit, …)` 级别的独立过期时间。
- 约定：缓存 key 常量集中放在各模块 `dal/redis/RedisKeyConstants`（如 system 的 `user_role_ids`、`permission_menu_ids`）。

### 3.5 guanghe-spring-boot-starter-security（认证鉴权）

- **认证**：`TokenAuthenticationFilter`（OncePerRequestFilter）
  1. 从 `Authorization` 头或 `token` 参数取令牌（`SecurityProperties.tokenHeader/tokenParameter`）；
  2. 调 `OAuth2TokenCommonApi.checkAccessToken` 校验，构建 `LoginUser`（id、userType、tenantId、scopes、过期时间）；
  3. 校验 `/admin-api`、`/app-api` 的 `userType` 是否匹配；
  4. 写入 Spring Security 上下文（`TransmittableThreadLocalSecurityContextHolderStrategy`，支持异步/线程池传递）；
  5. `mock-enable=true` 时支持 `test{userId}` 形式模拟登录（**仅 local 环境开启**）。
- **授权**：`GuangheWebSecurityConfigurerAdapter` 统一 `authorizeHttpRequests`；各模块通过实现 `AuthorizeRequestsCustomizer` 追加自有放行规则（如 infra 放行 `/druid/**`、`/actuator/**`、文件读取 `/infra/file/*/get/**`）。
- **鉴权注解**：`@PreAuthorize("@ss.hasPermission('system:user:query')")`，由 `SecurityFrameworkService` 代理到 `PermissionCommonApi`。
- **操作日志**：`operatelog/*`（`LogRecordServiceImpl`）把 `@LogRecord` 的 SpEL 结果结构化写入 `system_operate_log`，并注册 `AdminUserParseFunction`、`DeptParseFunction` 等把 ID 翻译成名称。
- **异常出口**：`AuthenticationEntryPointImpl`（401）、`AccessDeniedHandlerImpl`（403）。

### 3.6 guanghe-spring-boot-starter-biz-data-permission（行级数据权限）

- 注解 `@DataPermission(enable=false)` 可临时关闭；AOP `DataPermissionAnnotationInterceptor` + `DataPermissionContextHolder` 控制上下文。
- `DataPermissionRuleHandler` 基于 `InnerInterceptor` 改写 SQL：对命中规则的表追加 `dept_id` / `user_id` 条件。
- `DeptDataPermissionRule`：读取 `PermissionCommonApi.getDeptDataPermission(userId)`，支持「全部 / 指定部门 / 仅本部门 / 本部门及以下 / 仅本人」。
- 表的登记在业务模块完成，例如 `system` 的 `DataPermissionConfiguration`：

```java
rule.addDeptColumn(AdminUserDO.class);            // 默认 dept_id
rule.addDeptColumn(DeptDO.class, "id");
rule.addUserColumn(AdminUserDO.class, "id");
```

### 3.7 guanghe-spring-boot-starter-biz-tenant（多租户，当前关闭）

- 上下文：`TenantContextHolder`；Web 入参由 `TenantContextWebFilter` 从 `tenant-id` / `visit-tenant-id` 头解析。
- 数据隔离：`TenantDatabaseInterceptor`（MyBatis-Plus `TenantLineHandler`）自动追加 `tenant_id` 条件；继承 `TenantBaseDO` 的表参与隔离，`@TenantIgnore` 或配置 `guanghe.tenant.ignore-tables` 的表跳过。
- 缓存隔离：`TenantRedisCacheManager`；消息隔离：Redis/RabbitMQ/Kafka/RocketMQ 各自的拦截器；任务隔离：`@TenantJob`。
- 拦截：`TenantSecurityWebFilter` 校验租户可用性，`TenantVisitContextInterceptor` 处理跨租户访问。
- **当前配置**：`guanghe.tenant.enable: false`（单企业部署，关闭隔离），`ignore-caches` 中登记了 `user_role_ids`、`permission_menu_ids` 等公共缓存。

### 4.3 登录流程（`AdminAuthService#login`）

```
前端 POST /admin-api/system/auth/login
  └─ validateCaptcha(reqVO)                 // guanghe.captcha.enable 控制；anji-plus 校验并消费
     └─ authenticate(username, password)    // 用户存在？密码匹配？状态正常？
        │   失败 → 写 system_login_log(BAD_CREDENTIALS/USER_DISABLED) 并抛业务异常
        └─ 可选：socialType 非空 → 绑定社交账号
           └─ createTokenAfterLoginSuccess  // OAuth2TokenService.createAccessToken
              └─ 写 system_login_log(SUCCESS) → 返回 {accessToken, refreshToken, expiresTime, userId}
```

要点：

- 方法与类上 `@DataPermission(enable = false)`，避免登录过程被数据权限改写 SQL；
- 令牌是**有状态**的（落库 + 缓存），登出/踢人只需删除记录；
- `TokenCleanJob` 定期清理过期令牌；
- 前端 `Authorization: Bearer {accessToken}`，401 时用 `refreshToken` 做**无感刷新**（并发请求排队，刷新完成后重放）。

### 4.4 权限计算模型

```
用户 ──(system_user_role)──▶ 角色 ──(system_role_menu)──▶ 菜单
                                   │
                                   └─ dataScope：1 全部 / 2 指定部门 / 3 本部门 / 4 本部门及以下 / 5 仅本人
```

- `PermissionService#hasAnyPermissions(userId, permissions…)`：先查「用户启用的角色」，再按 `permission` 标识反查菜单，只要角色与菜单角色集合有交集即通过；超管角色直接通过。
- 缓存：`getUserRoleIdListByUserIdFromCache`、`getMenuRoleIdListByMenuIdFromCache`、`getMenuIdListByPermissionFromCache`，变更时用 `@CacheEvict` 精确失效。
- 数据权限：`getDeptDataPermission(userId)` 返回 `{all, deptIds, self}`，由 `DeptDataPermissionRule` 转成 SQL 条件。
- 前端侧：登录后调 `/system/auth/get-permission-info` 拿到 `user/roles/permissions/menus`，`permissionStore.generateRoutes()` 把菜单转成路由并 `router.addRoute`，按钮级用 `v-hasPermi` / `v-hasRole` 指令。

| 配置类 | 作用 |

### 5.2 文件存储设计

```
FileController.upload(file)
  └─ FileService.createFile(content, name, directory, configId?)
       ├─ 选配置：configId 为空时取 FileConfigService 的默认配置
       ├─ FileClientFactory.getFileClient(configId)     // 客户端按配置缓存
       ├─ client.upload(content, path, type)            // DB/Local/Ftp/Sftp/S3
       └─ 落库 infra_file（url、path、size、type、configId）

FileController.get/{configId}/**  → Security 放行（免登录下载，路径不可猜）
```

- `AbstractFileClient`：统一 `id/path/init/refresh/upload/delete/getContent` 骨架，子类只实现存储细节；
- `FilePathUtils`：日期分目录 + UUID 文件名；`FileTypeUtils`：按扩展名/MIME 推断类型；
- 配置变更时 `FileConfigServiceImpl` 调 `createOrUpdateFileClient` 热刷新，无需重启。

### 5.3 系统在线更新（`SystemUpdateServiceImpl`）

1. `validateAndStage`：后端只接受 `guanghe-server*.jar`；前端只接受含 `index.html` 的 zip（兼容顶层 `html/` 目录）；
2. 文件落暂存目录，`SystemUpdateProperties` 提供各目录路径；
3. 更新时加 `ReentrantLock` 防并发，`volatile` 字段维护 `updating/progressMessage/lastUpdateTime/lastUpdateResult`；
4. 备份旧文件 → 替换 → 通过进程/脚本触发重启，前端轮询 `getStatus` 展示进度；
5. 支持 `rollback` 回滚到上一版本。

## 6. 跨模块调用与接口契约

- **返回结构**：`CommonResult<T>{ code:0, data, msg }`；分页统一 `PageResult<T>{ list, total }` + `PageParam{ pageNo, pageSize }`。
- **错误码**：业务异常用 `exception(ErrorCodeConstants.XXX)`；HTTP 层错误由 `GlobalExceptionHandler` 转换；错误码区间在 `ServiceErrorCodeRange` 登记，新增模块前先分区，避免冲突。
- **模块 API 规范**（`api/xxx`）：
  - 接口以 `XxxApi` 命名，实现为 `XxxApiImpl`；
  - 参数/返回一律 DTO（`XxxReqDTO` / `XxxRespDTO`），不暴露 DO；
  - framework 中需要跨模块能力时，只依赖 `guanghe-common` 里的 `biz/**.XxxCommonApi` 接口。
- **异步解耦**：邮件、短信、站内信走 MQ（`MailSendConsumer`、`SmsSendConsumer`），生产端 `MailProducer`/`SmsProducer` 只投递消息，发送结果写各自 `*_log` 表。

## 9. 安全与性能设计

| 主题 | 措施 |
|---|---|
| 认证 | OAuth2 有状态令牌、可刷新、可吊销；令牌过滤器统一入口 |
| 授权 | 菜单/按钮权限标识 + `@PreAuthorize`；行级数据权限按部门/本人隔离 |
| 网络与报文 | 白名单放行、可选 XSS 过滤、可选报文 AES/RSA 加密、API 签名 `@ApiSignature` |
| 防刷 | `@RateLimiter`（按 IP/用户/节点/表达式）、验证码、短信验证码限频（`guanghe.sms-code.*`） |
| 幂等与并发 | `@Idempotent`、`@Lock4j` 分布式锁 |
| 敏感数据 | 字段级 `EncryptTypeHandler`、返回脱敏注解、日志中不打印令牌与密码 |
| 性能 | Redis 二级缓存（角色/菜单/字典/配置）、多数据源读写分离、分页查询、批量插入、`lazy` 从库初始化、慢 SQL 记录（Druid `slow-sql-millis: 100`） |
| 稳定性 | 全局异常兜底 + 错误日志落库、任务失败写 `infra_job_log`、MQ 未确认消息重投（`RedisPendingMessageResendJob`） |

## 10. 部署架构

### 10.1 一体化部署包（`release/gsite-deploy/`）

```
gsite-deploy/
├─ config.bat        唯一配置源：WEB_PORT=80、BACKEND_PORT=2000、SPRING_PROFILE=deploy、JVM 内存等
├─ setup.bat / restart-all.bat      首次安装 / 日常重启（按 config.bat 重新渲染所有配置）
```

## 11. 二次开发指引

### 11.1 新增一个业务模块

1. 在根 `pom.xml` 注册 `<module>`，并在 `guanghe-server/pom.xml` 引入依赖；
2. 复制 `system` 的包骨架：`api / controller(admin,app) / service / dal / convert / enums / framework`；
3. 在 `enums/ErrorCodeConstants` 定义错误码（先在 `ServiceErrorCodeRange` 登记区间）；
4. Controller 路径按 `controller.admin.xxx` 包名自动挂 `/admin-api`，`controller.app.xxx` 挂 `/app-api`；
5. 需要新表时执行 SQL，并在 `DataPermissionConfiguration` 中按需注册数据权限字段；
6. 需要接口文档分组时新增 `XxxWebConfiguration#groupedOpenApi`。

### 11.2 新业务代码生成（推荐路径）

`系统工具 → 代码生成 → 导入表 → 编辑字段/配置 → 预览 → 下载`：

- 后端产物：DO、Mapper、Service、Controller、VO、ErrorCode；
- 前端产物：`index.vue` + `XxxForm.vue` + `api/xxx.ts`（模板由 `CodegenFrontTypeEnum` 决定，本仓库默认 `20 = Vue3 Element Plus`）；
- 生成配置见 `guanghe.codegen.*`：`front-type`、`vo-type`、`delete-batch-enable`、`unit-test-enable`、`import-enable`。

### 11.3 命名与编码约定

| 层 | 命名 | 说明 |
|---|---|---|
| 实体 | `XxxDO` | 继承 `BaseDO`；表名 `模块_业务` |
| Mapper | `XxxMapper extends BaseMapperX<XxxDO>` | 复杂查询用 `MPJLambdaWrapperX` |
| 服务 | `XxxService` / `XxxServiceImpl` | 校验在前、落库在中、事件/消息在后 |
| VO | `XxxSaveReqVO`、`XxxPageReqVO`、`XxxRespVO` | 校验注解写在 VO 上 |
| 转换 | `XxxConvert`（MapStruct） | 不手写 setter 堆叠 |
| 权限标识 | `模块:业务:动作` | 如 `system:user:query`、`infra:file:delete` |

### 11.4 测试

- 纯逻辑：`BaseMockitoUnitTest`；
- 需要 DB：`BaseDbUnitTest`（H2 + `create_tables.sql` / `clean.sql`）；
- 需要 Redis：`BaseRedisUnitTest`；
- 二者都需要：`BaseDbAndRedisUnitTest`；

## 12. 当前限制与后续演进

1. **多租户关闭**：`guanghe.tenant.enable: false`，面向单企业部署；如需 SaaS 化，打开开关并补齐 `ignore-tables` / `ignore-caches`。
2. **部分安全能力默认关闭**：`guanghe.xss.enable: false`、`guanghe.api-encrypt.enable: false`，对外网暴露前建议评估开启。
3. **单体部署**：WebSocket 默认 `sender-type: local`，多实例部署时需切换为 `redis`/`rocketmq`/`kafka`/`rabbitmq` 才能跨节点广播。
4. **模块精简**：AI、ERP、IoT、商城等模块已从主干物理移除（见根 `pom.xml` 注释），需要时从上游同步回来并补依赖。
5. **本地调试开关**：local 配置里 `guanghe.security.mock-enable: true`（可用 `test{userId}` 模拟登录）、`guanghe.captcha.enable: false`、`guanghe.access-log.enable: false`，生产 profile 必须全部为安全取值。
6. **系统自更新**具备备份与回滚，但仍建议在维护窗口执行，并保证上传包与当前版本兼容。
